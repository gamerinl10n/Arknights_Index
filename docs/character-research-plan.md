# 인물 자료와 제삼자 언급 검색 개발 계획

사용자 요청일: 2026-11-16 (Asia/Shanghai). 이 문서는 후속 원격 개발의 작업 기준이며, 아래 기능은 아직 구현·운영 검증되지 않았다.

## 목표와 현재 상태

번역 조사에서 인물의 기본 자료와 발화를 함께 확인하고, 상대를 직접 부르는 경우와 다른 사람에게 그 인물을 언급하는 경우를 문맥으로 비교할 수 있게 한다.

- 현재 `character_catalog.py`는 `character_table.json`의 `char_` ID만 적재한다. 박사처럼 해당 표 밖에 있는 인물이 누락될 수 있다. `characters.json`에는 현재 박사 항목이 없다. 프로필 원문을 수집하는 경로와 프로필 화면도 없다.
- 현재 두 인물 검색은 화자 A의 대사에 대상 B의 이름·등록 별칭이 포함되는 조건이다. 가까운 B의 발화는 정렬 보조이며 실제 청자를 뜻하지 않는다.
- 원본 pin은 `dataset-source.json`에서 관리한다. 일일 원본 검사와 검증 후 PR 제안 흐름을 재사용한다. 저장소의 PR 생성 정책으로 수동 인계가 필요할 수 있다.
- 캐릭터 음성 표의 선행 조사는 있지만 재생 가능한 음원 연결은 검증되지 않았다. 최신 원본에서 다시 조사해야 한다.

## 1. 제삼자 언급 검색을 먼저 구현

예: **켈시가 박사와 대화하는 문맥에서 Mon3tr를 어떤 표현으로 언급하는가?**

| 입력 | 의미 | 예 |
| --- | --- | --- |
| 화자 | 찾을 발화의 인물 A | 켈시 |
| 언급 인물 | 발화 본문에서 이름·등록 별칭을 찾을 인물 B | Mon3tr / M3 |
| 제삼자 언급 후보 버튼 | B의 직접 응답이 가까운 후보와 구분하여 문맥을 좁힘 | 켜기 |
| 주변 대화 인물 (선택) | 같은 분기의 가까운 발화에서 확인할 인물 C | 박사 |

기존 `speaker`와 `target`을 유지하고 `mention_mode=all|third_party_candidate`, `interlocutor`를 추가한다. 기본값 `all`은 기존 결과·정렬과 호환된다. 모드 활성화에는 서로 다른 A와 B가 필요하며 C가 있으면 A/B와 다른 공식 또는 명시적 인물 ID여야 한다. 미등록 인물은 정확한 원문 화자 표기로 검색하되 이름 유사도로 합치지 않는다.

첫 구현의 후보 기준은 같은 스토리·같은 분기에서 현재 검색의 인접 발화 범위(방향별 최대 6개 텍스트 행·물리 60행)를 재사용한다. 화자 없는 행은 그 자체로 상대 증거가 아니다. A 이외의 첫 발화자를 각 방향에서 확인하고 분기 경계에서 멈춘다. B의 인접 발화가 있으면 제삼자 후보에서 제외한다. C 지정 시 인접 발화자가 C인 근거가 최소 하나 있어야 한다. C 미지정 시 A/B 이외의 명시적 발화자가 최소 하나 있어야 한다. 다른 화자를 건너뛰어 원하는 C를 찾지 않는다.

이는 **제삼자 언급 후보** 필터다. C가 실제 청자라는 판정, B가 장면에 없다는 판정, 발화 속 모든 표현이 B를 가리킨다는 판정을 하지 않는다. 결과에는 근거가 된 주변 발화·분기·출처를 확인할 수 있게 한다. B 이름이 생략된 대사와 별칭 미등록 용례는 누락될 수 있다. 장면 전체를 검증하는 기능은 별도 후속 과제다.

구현 위치:

- `search_queries.py`: 인접 발화 증거를 재사용하는 공통 조건과 후보 필터. 페이지 나눈 뒤 필터링하지 않고 집계·정렬 전에 적용한다.
- `multilingual_search.py`: 원래 일치 언어에서 인물 조건을 검증한 뒤 검증된 대응으로 정규화한다. 대표 언어만 보고 후보를 새로 판정하지 않는다.
- `app.py`: 새 인수 검증, 기존 상세 API 호환, 근거 메타데이터.
- `web/ui/form-state.mjs`, API/필터 모듈과 `web/app.js`: 공유 URL·검색 식별자·캐시 키·뒤로 가기·초기화·인물 교환에 새 조건을 포함한다. 화면 언어 변경과 업데이트 전 URL 보존도 확인한다.
- `translations.py`, 검색 폼과 도움말: 네 언어 버튼·필드·후보 안내. 주변 인물은 모드를 켰을 때 표시하고 키보드 조작 및 모바일 폭을 검증한다.

완료 기준: 기존 기본 검색 응답 호환, 같은 분기 C 후보 포함/B 직접 인접 제외/다른 분기 제외/불명 화자만 있는 경우 제외/A·B·C 중복 입력 검증, 별칭·다국어·페이지별 개수 일관성, URL 복원·뒤로 가기·새 검색 캐시 분리. 실제 켈시/Mon3tr/박사 원본 용례를 출처와 함께 수동 확인하되 합성 fixture를 공식 대사로 제시하지 않는다.

## 2. 박사와 비오퍼레이터 인물 자료 보강

먼저 박사 검색의 실제 원문 화자 표기, 선택지, 플레이어명 변수와 언어별 표기를 조사한다. 선택지와 플레이어 변수를 모두 박사의 발화로 자동 치환하지 않는다. 검색 가능한 인물 등록과 프로필 본문 수집을 별도 작업으로 진행한다.

오퍼레이터 표 밖 인물은 명시적으로 관리하는 보조 사전에 출처·언어·revision·원본 키를 보존하고 기존 자동 생성 사전과 병합한다. 게임의 공식 ID가 없는 항목은 충돌하지 않는 로컬 ID임을 표시한다. 데이터 재생성 후에도 보조 항목이 사라지지 않아야 한다. 초상화가 없는 경우 기본 아이콘을 제공한다.

프로필은 공개 원본의 실제 자료 경로와 스키마를 조사한 뒤 기본 정보·기록·관련 대사 링크를 제공한다. NPC/박사에게 오퍼레이터 전용 프로필이 있다고 가정하지 않는다. 공식 프로필이 없으면 확인된 자료와 출처만 표시하고 본문을 창작하지 않는다. 언어별 미공개·자료 없음·수집 미지원을 구분한다. 프로필 인물이 검색 자동완성에 나타나는 기준과 대사 없는 인물을 탐색하는 경로도 분리한다.

완료 기준: 박사의 등록·다국어 이름·출처 확인, 기존 오퍼레이터 ID와 충돌 없음, 재생성 시 보존, 선택지 오분류 없음, 프로필 누락 상태 표시, 원본 SHA와 출처 추적. 실제 자료를 확인하기 전에는 프로필 보강 완료로 보고하지 않는다.

## 3. 대사·프로필 갱신을 같은 검증 흐름에 연결

기존 일일 원본 검사와 데이터 발행을 확장한다. 새 자료별 언어·원본 경로·개수·revision·삭제/누락·파싱 실패를 보고하고, 기존 스토리의 감소 차단과 전체 대응 검증을 유지한다. 프로필·보조 사전·음성 텍스트 파서도 데이터 입력 해시에 포함한다. UI만 바꾼 배포로 데이터가 갱신되었다고 기록하지 않는다.

완료 기준: 새로운 SHA 후보 생성부터 검증 보고서·PR·데이터 발행·실제 배포 상태 확인까지 재현. 변경 없는 원본에서는 중복 PR을 만들지 않는다. 원본 덤프·DB는 커밋하지 않고 배포 스냅샷 450MiB 예산을 확인한다.

## 4. 캐릭터 음성 텍스트와 재생 추가

이번 요청으로 캐릭터 음성 자료의 보강을 개발 범위에 다시 포함한다. 별도 검색 화면을 늘리기보다 기존 인물 탐색/결과에서 자료 유형을 구별하여 제공한다. `charword_table.json`의 최신 구조를 다시 조사하고 charId·charWordId·voiceId·언어·해금 조건·출처를 보존한다. 스토리 대사와 음성 텍스트를 별개 자료로 취급하고 동일 문장이라는 이유로 같은 녹음으로 연결하지 않는다.

음원 재생은 실제 자산 출처·언어·식별자 대응·접근 가능 여부·이용 조건·CORS/Range와 트래픽을 확인한 연결만 제공한다. 상대 리소스 키를 HTTPS 주소로 추정하지 않는다. 음원이 확인되지 않은 항목은 재생 버튼을 노출하지 않는다. 텍스트 언어와 녹음 언어를 구분하고, 모바일에서 사용자가 누르기 전 자동 재생을 전제로 하지 않는다.

완료 기준: 최신 네 지역 텍스트 범위·누락 보고, 언어별 ID 대응 검증, 유효한 음원 한 건 이상 실제 재생 및 실패 처리 검증. 스토리 음원은 별도 검증을 유지한다. 기존 음성 조사 문서는 당시의 이력이며 이 계획과 충돌하는 향후 범위는 이 문서를 따른다.

## 기존 기능 재사용 기준

사용자 추가 지시: 새 요구는 기존 기능과 화면을 우선 확장하고, 중복 기능과 조작을 늘리지 않는다.

- 제삼자 검색은 기존 화자·대상 입력과 자동완성을 그대로 사용한다. 별도 검색 페이지 대신 버튼 하나를 추가하고, 주변 대화 인물 조건은 활성화했을 때만 표시한다.
- 인접 발화 SQL은 단일 언어·다국어 검색이 공유하도록 추출한다. 기존 정렬과 새 후보 필터가 서로 다른 기준을 갖지 않게 한다.
- 근거 확인은 기존 문맥 펼치기·출처 모달·이름 강조·언어 버튼을 재사용한다. 같은 내용을 보여주는 패널을 중복 추가하지 않는다.
- 프로필·음성은 기존 인물 및 결과 진입점에서 연결한다. 자료 유형을 명확히 구별하되 유형마다 별도 검색 화면·설정 체계를 만들지 않는다.
- 결과 내 좁히기는 기존 검색 조건과 재검색을 우선 활용한다. 호칭 비교·수집함은 기존 결과/언어 표시/공유 URL만으로 목적을 달성할 수 있는지 먼저 검증하고, 부족한 작업만 추가한다. 앞서 제안된 기능 목록 전체를 일괄 구현하는 것으로 해석하지 않는다.
- API 클라이언트·폼 상태·기록 복원·캐시·갱신 워크플로는 기존 모듈을 확장한다. 새로운 프레임워크나 병렬 데이터 경로는 측정된 필요가 있을 때만 검토한다.
- 최적화는 같은 스냅샷의 결과 수·순서·원문·출처와 시간·메모리를 비교해 판단한다. 기본 모드의 조작 수와 초기 화면 복잡도가 불필요하게 늘지 않는지도 완료 기준에 포함한다.

## 원격 개발 인계

각 단계는 기능 브랜치와 독립 PR로 진행한다. 다음 작업은 1번 검색 기능이며, 2번의 박사 표기 조사를 함께 수행해야 예시를 실제 데이터에서 검증할 수 있다. 기능 구현 PR에서 사용자에게 보이는 도움말과 패치노트를 갱신한다. 현재 준비 PR은 기능 출시로 기록하지 않는다.

검사는 `docs/development.md`의 Python 단위 검사·JavaScript 검사·문법 검사와 변경 범위에 맞는 브라우저 검증을 사용한다. 실제 데이터가 없으면 합성 검사 결과와 운영 데이터 미검증을 구분해 보고한다. 시간 기반 반복 개발 작업은 이 문서만으로 생성되지 않는다.
